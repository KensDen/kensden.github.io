Compliance as Code

Compliance Defined in YAML.
Evidence Delivered Automatically.

Karrier's control mappings are plain YAML — readable by engineers and auditors alike. Thresholds, artifact linkages, and framework mappings are all version-controlled and fully auditable.

nist-800-53-rev5.yaml (excerpt) Control Mapping 
# NIST SP 800-53 Rev 5 — Karrier Control Mappings
# Override thresholds in project's .karrier-oscal.yml

framework:
  name: "NIST SP 800-53 Revision 5"
  version: "5.1.1"
  baseline: "MODERATE"

controls:
  SI-2:
    name: "Flaw Remediation"
    family: "System and Information Integrity"
    automated: true
    artifacts:
      - file_pattern: "dependency-check-report.json"
        parser_type: "trivy_vuln"
        scanner_name: "Trivy (Vulnerabilities)"
    thresholds:
      critical: 0    # Zero-tolerance
      high:     0    # Zero-tolerance
      medium:   10   # Up to 10 allowed

  IA-5:
    name: "Authenticator Management"
    automated: true
    artifacts:
      - file_pattern: "gitleaks-report.json"
        parser_type: "gitleaks"
    thresholds:
      critical: 0    # No secrets — ever

  SR-3:
    name: "Supply Chain Controls"
    automated: true
    artifacts:
      - file_pattern: "dependency-check-report.json"
        parser_type: "trivy_filesystem"
      - file_pattern: "*-cyclonedx-sbom.json"
        parser_type: "cyclonedx_sbom"
    thresholds:
      critical: 0
      high:     0

Every line has a reason.

Karrier's control mappings are not black-box configuration. Each entry is explicit, auditable, and version-controlled. Auditors, program managers, and engineers can all read the same file and understand exactly what is being assessed, how, and at what thresholds.

  • 1
    Control ID — maps directly to the framework control identifier. Cross-references are maintained automatically across all four frameworks.
  • 2
    artifacts — specifies which scanner output provides evidence, which parser interprets it, and what name appears in the OSCAL output and dashboard.
  • 3
    thresholds — defines pass/fail criteria per severity level. Critical and high are typically zero-tolerance. Thresholds can be overridden per-project without modifying the central mapping.
  • 4
    Multiple artifacts — SR-3 draws from both Trivy and SBOM output simultaneously. Many-to-many scanner/control relationships are first-class patterns.
  • 5
    Version-controlled — every threshold change is a git commit. Auditors can inspect the complete history of compliance policy decisions at any point in time.
